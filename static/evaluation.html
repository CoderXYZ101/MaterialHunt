Model evaluation

Reproducible results for the machine-learning models that run on your device.

Read this first. These models are small and trained on little data. They are a screening aid. The results below say exactly how rough they are, including where they did badly. Nothing here replaces a datasheet or a lab test.

3. Library yield model: does more data help?

The same question in the in-browser (JavaScript) version, 8-fold test on the 48 library grades, measured on the version that ships with the site: library grades only gave R² 0.26 and an average error of 226 MPa (53%); with the 312 steels added to the training side, R² 0.48 and 214 MPa (54%). So more data clearly raised R², but the average percentage error barely moved. The ML Lab recomputes these live on your device.

4. Reproduce it yourself

Everything above is produced by one script that reads only files in the project. With Python installed:

pip install scikit-learn numpy
python evaluation/evaluate.py

It writes static/data/evaluation.json, which this page displays. Seeds are fixed. Small differences in the last digit between machines are normal. The same checks also run live in your browser: open the ML Lab and press "Train and test the model" (slow motion shows each step).

The in-browser model is written from scratch in JavaScript, so its numbers differ slightly from the Python figures here; the ML Lab shows its own, live.

5. Known limits

  • The library has only 48 grades. Library values are typical datasheet numbers, and real strength depends on heat treatment.
  • The steel model only covers iron-based alloyed steels in roughly the 1,000 to 2,500 MPa range. For anything else it refuses and the simulator uses a library value or the weaker library model.
  • The independent check is tiny (see the table). We publish it because it is the honest result, not because it is flattering.
  • The "spread" between trees is a rough sign of uncertainty, not a calibrated confidence interval.
