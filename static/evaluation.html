Model evaluation

Reproducible results for the machine-learning models that run on your device.

Read this first. These models are small and trained on little data. They are a screening aid. The results below say exactly how rough they are, including where they did badly. Nothing here replaces a datasheet or a lab test.

Which model is used when

  1. Your mix matches a library grade (total difference within 6 weight-percent): the grade's typical datasheet yield. This is a table value, not machine learning.
  2. Otherwise, an iron-based alloyed steel inside the steel model's range (at least 40 atomic-% iron, only elements the model knows, and close to the 312 steels it learned from, whose yield strengths run from about 1,000 to 2,500 MPa): the steel model (extra-trees, 80 trees, trained on 312 measured steels).
  3. Otherwise, a mix inside the library model's range (close to compositions among the 48 library grades and the 312 steels): the library model (random forest, 80 trees, trained on the 48 library grades plus the 312 steels). A rough guide.
  4. Otherwise (outside both models' ranges, or the Estimator switch is on Rules): no ML estimate is made. The rough composition formula is used (average error about 105%) and the verdict is marked low reliability.

If you switch to My ML, the model you trained replaces steps 2 and 3 for the property it predicts.

The sections below test the steel model (step 2) and the library model (step 3).

2. Independent check

The cross-validation above only tests on the same dataset. For an independent check, the steel model (which never saw our library) predicts the yield strength of each library grade it considers inside its range, and we compare with the library value.

GradeLibrary value (MPa)Model said (MPa)
Maraging steel 18Ni30019001279

Only 1 of the 48 library grades was inside the steel model's range (the other 47 are stainless, aluminium, nickel and other alloys it was not trained for). On that one grade the error was about 33%. One grade proves very little, and it shows the model is rough outside its training data. Library values are typical datasheet values, which depend on heat treatment; this is a small, honest check, not a proof.

How to read this: on the steels the model is usually within a few percent of the measurement, because they are alike and plentiful. On the varied library grades the errors are large for some alloys. That is why the library model is labelled a rough guide and why the Simulator prefers a grade's datasheet value whenever your mix matches one. You can repeat the test yourself with the script below, or watch it happen live in the ML Lab.

5. Reproduce it yourself

Everything above is produced by one script that reads only files in the project. With Python installed:

pip install scikit-learn numpy
python evaluation/evaluate.py

It writes static/data/evaluation.json and fills the numbers in this page. Seeds are fixed. Small differences in the last digit between machines are normal. The same checks also run live in your browser: open the ML Lab and press "Train and test the model" (slow motion shows each step).

The in-browser model is written from scratch in JavaScript, so its numbers differ slightly from the Python figures here; the ML Lab shows its own, live.

6. Known limits

  • The library has only 48 grades. Library values are typical datasheet numbers, and real strength depends on heat treatment.
  • The steel model only covers iron-based alloyed steels in roughly the 1,000 to 2,500 MPa range. For anything else it refuses, and the simulator tries the library model. If the mix is outside that model's range too, no ML estimate is made at all.
  • Even the best case is not dependable engineering prediction: the library model is off by roughly half on average. Use datasheets and tests for decisions.
  • The independent check is tiny (see the table). We publish it because it is the honest result, not because it is flattering.
  • The "spread" between trees is a rough sign of uncertainty, not a calibrated confidence interval.
