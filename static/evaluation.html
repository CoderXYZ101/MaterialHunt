Model evaluation

Reproducible results for the machine-learning models that run on your device.

Read this first. These models are small and trained on little data. They are a screening aid. The results below say exactly how rough they are, including where they did badly. Nothing here replaces a datasheet or a lab test.

Which model is used when

  1. Your mix matches a library grade (total difference within 6 weight-percent): the grade's typical datasheet yield. This is a table value, not machine learning.
  2. Otherwise, an iron-based alloyed steel inside the steel model's range (at least 40 atomic-% iron, only elements the model knows, and close to the 312 steels it learned from, whose yield strengths run from about 1,000 to 2,500 MPa): the steel model (extra-trees, 80 trees, trained on 312 measured steels).
  3. Otherwise, a mix inside the library model's range (close to compositions among the 48 library grades and the 312 steels): the library model (random forest, 80 trees, trained on the 48 library grades plus the 312 steels). A rough guide.
  4. Otherwise (outside both models' ranges, or the Estimator switch is on Rules): no ML estimate is made. The rough composition formula is used (average error about 105%) and the verdict is marked low reliability.

If you switch to My ML, the model you trained replaces steps 2 and 3 for the property it predicts.

The sections below test the steel model (step 2) and the library model (step 3).

2. Independent check

The cross-validation above only tests on the same dataset. For an independent check, the steel model (which never saw our library) predicts the yield strength of each library grade it considers inside its range, and we compare with the library value.

Only 1 of the 48 library grades was inside the steel model's range (the other 47 are stainless, aluminium, nickel and other alloys it was not trained for). On that one grade the error was about 33%. One grade proves very little, and it shows the model is rough outside its training data. Library values are typical datasheet values, which depend on heat treatment; this is a small, honest check, not a proof.

5. Across material families: leave one family out

A tougher test than leave-one-out. Here every grade of a family is hidden at once (for example all 12 stainless steels), the library model trains on the other families plus the 312 steels, and then predicts the hidden family. This is what happens when someone asks about a kind of alloy the model has never seen.

Overall, with whole families hidden, the library model's average error is 85% and R² is 0.31 (compare 47% and 0.59 when only single grades are hidden).

What this means: the library model does not carry over from one family to another. In several families it does worse than guessing the average. That is why the simulator refuses an ML estimate when a mix is far from anything the model learned, and why it prefers the datasheet value for a grade it knows.

Why Max and Ultra train on your own data: compare the two error columns. When some of a family has been seen (fourth column), the error is usually lower than when the whole family is hidden (third column), and sometimes much lower (stainless steel falls from 164% to 42%). It does not help in every family: for titanium, cobalt, nickel alloys and magnesium there were too few grades to learn from. Accuracy comes from having data of the kind you ask about, not from a bigger model (a 400-tree model did no better, see section 3).

Steels: whole groups of similar compositions hidden

The steel model's ordinary cross-validation hides random steels, which are often very like the ones it trained on. A stricter test hides a whole group of similar steels at once (found by clustering the compositions).

Overall with whole groups hidden: average error 246 MPa (17%), R² -0.05, compared with 83 MPa and R² 0.84 in ordinary cross-validation and 229 MPa for guessing the average.

What this means: the steel model's high score holds for steels that are close to ones it learned from. For a new kind of steel (a whole group hidden), it is no better than guessing the average, and in some groups it is worse. The simulator's range check helps by refusing mixes far from the training data, but a mix inside that range can still be a new kind of steel. Treat a steel-model answer as trustworthy mainly when your steel is like the 312 it knows.

Is this an independent validation? No. Every number above still comes from the same public steels table and our own 48-grade library. A truly independent validation needs a separately collected set of measurements, which we do not have yet. We list it as missing, not done. If you have measured values for steels or alloys, post them in the Forum under "Check my result".

6. Calculation checks against reference values

The simulator's non-ML calculations were also checked against reference values.

Density of the mix (48 library grades)

The simulator mixes densities so that volumes add. Across all 48 grades the mean difference from the datasheet density is 1.37% (worst 4.59%, Aluminium bronze (C95400)); 44 of 48 are within 3%. An earlier version averaged densities by weight and was off by 1.88% on average and up to 11.45%; the check found that, and it was fixed.

Across the 48 library grades, the raw-element cost is off from the middle of the grade's stockist price range by a median factor of 2.38; 14 of 48 are within 1.5×, 21 within 2×, and the worst is 9.0×. That is why, when your mix matches a library grade, the simulator shows the grade's price range instead.

7. Reproduce it yourself

Everything above is produced by one script that reads only files in the project. With Python installed:

pip install scikit-learn numpy
python evaluation/evaluate.py

It writes static/data/evaluation.json and fills the numbers in this page. Seeds are fixed. Small differences in the last digit between machines are normal. The same checks also run live in your browser: open the ML Lab and press "Train and test the model" (slow motion shows each step).

The in-browser model is written from scratch in JavaScript, so its numbers differ slightly from the Python figures here; the ML Lab shows its own, live.

8. Known limits

  • The library has only 48 grades. Library values are typical datasheet numbers, and real strength depends on heat treatment.
  • The steel model only covers iron-based alloyed steels in roughly the 1,000 to 2,500 MPa range. For anything else it refuses, and the simulator tries the library model. If the mix is outside that model's range too, no ML estimate is made at all.
  • Even the best case is not dependable engineering prediction: the library model is off by roughly half on average. Use datasheets and tests for decisions.
  • The independent check is tiny (see the table). We publish it because it is the honest result, not because it is flattering.
  • The steel model's 0.85 R² is for steels similar to its training data. With whole groups of similar steels hidden it scores about zero (section 5), so it is not a general steel predictor.
  • The simulator's melting point is a weighted average of the element melting points, not a phase diagram. Against ten published melting ranges it landed inside only some of them (see section 6), and it can be off by a couple of hundred degrees for nickel superalloys. Treat it as a rough warning, not a design limit.
  • The "spread" between trees is a rough sign of uncertainty, not a calibrated confidence interval.
